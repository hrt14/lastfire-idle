# ワーキングプラネット — 設計

原始からはじめて、時代を進めていくシリーズ。
はんじょうダッシュ（ラーメン一直線・ドリームパーク）とは別の並びで、
同じサイト `working-planet.hitobito.jp` に入れる。

このシリーズの中心は **工程**。
ものは一手でできあがらない。何段階かを通って完成品になる。
その一段ごとを、自分の足 → 人 → 設備、と順に手放していくのが遊びになる。

---

## 1. いまの形と、これからの形

### いまの形（はんじょうダッシュ）

```
寸胴 ──(丼)──▶ 席
```

作る場所が1つ、渡す場所が1つ。運ぶのは1回だけ。
これはこれで分かりやすいが、**自動化するものが「運ぶ」しかない**。

### これからの形

```
畑 ──(麦)──▶ 石うす ──(粉)──▶ 練り台 ──(生地)──▶ 焼き石 ──(パン)──▶ 仲間
```

作る場所が数珠つなぎになる。あいだの矢印ひとつひとつが「運ぶ仕事」で、
**矢印ごとに別々に自動化できる**。

ラーメンで言えば「麺を打つ → 茹でる → スープに入れる → 出す」。
時代が進むほど工程が増えて、覚えることも、手放せるものも増えていく。

---

## 2. 工程の仕組み

### 2-1. 置き場でつなぐ

新しい概念は入れない。いまの「寸胴」を一般化して **作業場（station）** にするだけ。

作業場はそれぞれ、

- **受け口**（前の工程から届くものが積まれる場所）
- **出し口**（できあがったものが積まれる場所）

を持つ。受け口が空なら止まる。出し口がいっぱいでも止まる。

| いまの呼び名 | これからの呼び名 | 受け口 | 出し口 |
|---|---|---|---|
| 寸胴 | 採取場（素材の作業場） | なし | あり |
| （なし） | 加工場 | あり | あり |
| 席 | 渡し先 | あり | なし（お金になる） |

つまり **席は「出し口のない作業場」**、**寸胴は「受け口のない作業場」**。
同じ型で書けるので、いまのコードの延長で足せる。

### 2-2. 運ぶのはこれまでどおり

プレイヤーの操作は変わらない。

- 出し口に近づく → 持ち上がる
- 受け口（または待っている仲間）に近づく → 置く

工程が増えても、やることは「拾って、置く」のくり返し。
覚えることが増えないまま、道のりだけが長くなる。

### 2-3. 詰まりが見える

工程が長いと、どこで止まっているかが分からないと苦しい。
作業場の上に、いまの状態を出す。

| 状態 | 出す文字 |
|---|---|
| 受け口が空 | 材料まち |
| 動いている | （進み具合の輪） |
| 出し口が満杯 | 満杯 |

「満杯」が並んでいたら、その先が詰まっている。
「材料まち」が並んでいたら、その手前が足りない。
これが見えるだけで、次に何を買えばいいかが分かる。

## 3. 自動化のはしご

工程ひとつ（矢印ひとつ）につき、手放しかたが3段ある。
**この3段が、このシリーズのいちばんの遊び。**

| 段 | 何を買うか | どうなるか | 値段の感じ |
|---|---|---|---|
| 1 | **はこび手**（人） | その区間だけを1人が往復する。1回ずつ、遅い | 安い |
| 2 | **速いはこび手**（獣・車輪・ロボ） | 同じ区間を、たくさん・速く運ぶ | 中くらい |
| 3 | **直結の設備**（とい・ベルト・管） | 区間そのものが消える。出し口から次の受け口へ直に落ちる | 高い |

3段目まで買うと、その工程は画面から「運ぶ仕事」として消える。
かわりに、そのぶん先の工程を自分で見るようになる。
工程が5つある時代なら、この3段が5セットある。

あわせて、作業場そのものを速くするものも置く。

- **職人**（その作業場に立つ）… その作業場だけが速くなる（いまの調理人と同じ）
- **道具の強化**（レベル制）… すべての作業場が速くなる（いまの業務用寸胴と同じ）

## 4. エンジンにどう足すか

`lib/shop.ts` に対する変更の見取り図。既存の2ステージは何も変えなくていい形にする。

### 4-1. ものの種類を、ステージが決める

いまは3種類で固定。

```ts
export type ItemKind = "main" | "food" | "goods";
```

これを文字列にして、ステージが自分で名前と見た目を決める。

```ts
export type ItemKind = string;

export type ItemSpec = {
  id: ItemKind;
  /** 画面に出す名前（「木の実」「焼き魚」） */
  name: string;
  /** 見た目の種類 */
  art: string;
};
```

はんじょうダッシュ側は `main` / `food` / `goods` をそのまま宣言すれば、いまのまま動く。

### 4-2. 作業場

`StoveSpec` を広げる。名前は `StationSpec` にして、`stoves` は別名で残す。

```ts
export type StationSpec = {
  id: string;
  pos: Vec;
  price: number;
  area: number;
  /** 受け取るもの。省略すると素材（何もいらない） */
  takes?: ItemKind;
  /** 作るもの */
  makes: ItemKind;
  /** 1つ作るのにかかる時間の倍率。既定 1 */
  work?: number;
  /** 受け口・出し口に積める数。既定 STOVE_CAPACITY */
  hold?: number;
  art?: string;
  label?: string;
  unlockAfter?: string;
};
```

状態はひとつ増えるだけ。

```ts
/** 作業場の受け口にたまっているもの */
hold: Record<string, number>;
```

作業場の毎フレームの処理:

1. `takes` があって `hold[id] <= 0` なら止まる（材料まち）
2. `ready[id]` が満杯なら止まる（満杯）
3. そうでなければ進める。1つできたら `hold[id] -= 1`、`ready[id] += 1`

### 4-3. はこび手は「区間」を持つ

いまのホール店員は「丼を運ぶ人」。これを「**この区間を運ぶ人**」にする。

```ts
export type HireSpec = {
  // ...いまのまま
  /** 運ぶ区間。to が "guest" なら、待っている人へ届ける */
  route?: { from: string; to: string | "guest" };
};
```

区間が決まっていると、

- 誰が何を運んでいるか、見ただけで分かる
- 取り合いが起きない
- 「この区間はまだ人がいない」が一目で分かる

選びかたはいまと同じ **くじ引き**（1〜5番目のなかから引いて、外れたら1.2秒待つ）。
これは動きが良かったので変えない。

区間の指定がない運び手（プレイヤー、いまの案内係）は、これまでどおり何でも運ぶ。

### 4-4. 直結の設備

```ts
export type EquipSpec = {
  // ...いまのまま
  /** ここをつなぐと、運ばなくても流れる */
  link?: { from: string; to: string };
};
```

`link` を持つ設備を買うと、毎フレーム `ready[from]` から `hold[to]` へ1つずつ流す。
見た目は、2点のあいだに樋・ベルト・管を描いて、流れているものを走らせる。

### 4-5. 渡し先（席）

いまの `SeatSpec.needs` が、そのまま「最後の工程の完成品」になる。
`mode` は `ride` / `table` / `shelf` をそのまま使える。

### 4-6. 放置ぶんの見積もり

いまは `min(作る速さ, 席の回転, 運ぶ速さ)`。
工程が増えるので、**いちばん遅い工程**で決まる形にする。

```
1秒あたり = min(
  工程1の速さ, 工程2の速さ, …, 工程nの速さ,
  区間1の運ぶ速さ, …, 区間nの運ぶ速さ,
  渡し先の回転
)
```

人も設備もない区間があれば、その区間の速さは 0。
つまり **どこか1区間でも手つかずなら、放置では稼げない**。
これは正しい。留守のあいだ、そこは誰も運んでいない。

## 5. 時代の並び

12。前半をこまかく割って、原始のうちに工程が2→5まで育つようにする。

| # | 時代 | つくるもの | 工程 |
|---|---|---|---|
| 1 | 火のはじまり | 焼き木の実 | 2 |
| 2 | 川と魚 | 焼き魚 | 3 |
| 3 | 狩りの草原 | 干し肉・毛皮 | 4 |
| 4 | 土器の村 | つぼ・煮こみ | 4 |
| 5 | 麦の実り | 平パン | 5 |
| 6 | 青銅の炉 | 道具・かざり | 5 |
| 7 | 城下町 | 織物・酒 | 6 |
| 8 | 港と航路 | 香辛料・砂糖 | 6 |
| 9 | 蒸気の工場 | 布・機械 | 7 |
| 10 | 電気の街 | 家電・自動車 | 7 |
| 11 | 情報の島 | 半導体・端末 | 8 |
| 12 | 軌道ステーション | 燃料・宇宙船 | 8 |

時代が上がると工程が1つずつ増える。
増えたぶんだけ完成品が高い（**完成品の単価 ≒ 基本単価 × 工程数**）ので、
「めんどうになったが、そのぶん儲かる」が釣り合う。

お金の呼び名も時代で変える（貝がら → 石 → 銭 → 円 → クレジット）。
ステージの `labels` に足すだけ。

## 6. 第1ステージ「火のはじまり」

工程2つ。ここで「拾って、置いて、また拾う」を覚える。

### 区画

| id | 名前 | 値段 | 何が増えるか |
|---|---|---|---|
| area-0 | たき火のまわり | 0 | 木の実の工程（2） |
| area-1 | 木の実の林 | 900 | 拾い場と焚き火が増える |
| area-2 | 川べり | 12,000 | 魚の工程（3）が入る |
| area-3 | ほら穴 | 90,000 | 保存（干す）が入って、夜も稼ぐ |

### 作業場と流れ（area-0）

```
木の実の木 ──(木の実)──▶ たき火 ──(焼き木の実)──▶ 丸太のベンチ（仲間）
```

| id | 名前 | takes | makes | 値段 |
|---|---|---|---|---|
| pick-1 | 木の実の木 | — | 木の実 | 0 |
| pick-2 | 木の実の木 | — | 木の実 | 180 |
| fire-1 | たき火 | 木の実 | 焼き木の実 | 0 |
| fire-2 | たき火 | 木の実 | 焼き木の実 | 700 |

渡し先は丸太のベンチ（`mode: "ride"` と同じ扱い。座って食べて、貝がらを置いていく）。

### 自動化のはしご（area-0）

| 買うもの | 何をするか | 値段 |
|---|---|---|
| ひろい手 | 木の実の木 → たき火 を運ぶ | 120 |
| くばり手 | たき火 → 仲間 へ運ぶ | 320 |
| 火の番 | たき火に立つ。その火が速くなる | 800 |
| 犬 | 木の実の木 → たき火 を、たくさん速く運ぶ | 3,000 |
| 木のとい | 林からたき火へ、転がして直結 | 9,000 |
| 石だたみの道 | たき火から仲間へ直結 | 26,000 |

### 強化（レベル制）

| id | 名前 | 効く先 |
|---|---|---|
| carry | かごを編む | 一度に持てる数（自分と仲間） |
| speed | わらじ | 足の速さ（自分と仲間） |
| cook | 火をあおぐ | すべての作業場の速さ |
| price | 味つけの石塩 | 完成品ひとつの値打ち |

### 集客

「けむり」「たいこ」「かがり火」。いまの のぼり旗・大提灯 と同じで、掛け算で効く。

## 7. 第2ステージ「川と魚」の骨子

工程3つ。ここで「途中で詰まる」を覚える。

```
川の罠 ──(魚)──▶ さばき台 ──(切り身)──▶ 焼き石 ──(焼き魚)──▶ 仲間
```

区間が3つあるので、はしごも3セット。
`さばき台` だけ人がいないと、前が満杯・後ろが材料まちになって止まる。
このとき **どこが止まっているかが画面で分かる**ことが大事なので、
「満杯」「材料まち」の見せかたはここで作り込む。

---

## 8. ラーメン一直線への逆輸入

工程の仕組みができたら、ラーメンにも足せる。いまの寸胴を割る。

```
製麺台 ──(麺)──▶ 釜 ──(茹で麺)──▶ 寸胴 ──(丼)──▶ 席
```

ただし **いまのセーブを壊さない**。
古い寸胴 `stove-1..5` はそのまま「丼を作る作業場」として残し、
製麺台・釜は区画2（製麺所）以降に足す新しい作業場にする。
古い寸胴は「材料がいらない代わりに遅い」、
新しい流れは「工程は増えるが、1杯あたりが高い」。
どちらを伸ばすかを選べる形にすると、作りなおしが要らない。

---

## 9. 難易度の考え方

- 完成品の単価 ＝ 基本単価 × 工程数。工程が長いほど1個が高い
- 区間の自動化は、その区間の「1秒あたり」を上げる買い物。
  いちばん遅い区間にしか効かないので、順ぐりに埋めるのが正解になる
- 放置は 8 時間まで、0.75 倍（いまと同じ）。
  ただし手つかずの区間が1つでもあると 0
- 一晩で1つ、二晩で全部の時代が仕上がるくらい。ドリームパークで取った目安と同じ

## 10. つくる順番

1. **エンジン**: `ItemKind` を文字列にして、`ItemSpec` をステージに持たせる（既存2つは据え置き）
2. **エンジン**: `StationSpec`（`takes` / `makes` / `hold`）と `state.hold` を足す。
   受け口が空なら止まる・満杯なら止まるを入れる
3. **見た目**: 作業場の「材料まち」「満杯」、受け口に積まれたものの絵
4. **エンジン**: `HireSpec.route` を足して、区間ばんの運び手を入れる
5. **エンジン**: `EquipSpec.link` を足して、直結の設備を入れる
6. **ステージ**: 「火のはじまり」を作って、工程2つで通しで遊べるようにする
7. **ステージ**: 「川と魚」で工程3つ。詰まりの見せかたを詰める
8. そこから先の時代を、同じ型で並べていく

1〜6 まで通せば、遊べる形になる。
