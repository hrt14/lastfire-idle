# ラーメン一直線 第5区画「ラーメンスタジアム」仕様書 v0.1

幻の総本店（第4区画）の先に、**100億円〜1000億円のものだけで組んだ最後の区画**を足す。
まだ実装していない。ここに書いた数字はすべて仮値で、素振り（自動プレイヤー）で測って動かす。

先に決めたこと。

- 置くものは**すべて 100億円以上・1000億円以下**。それより安いものは、この区画には出さない
- 難しさは**値段ではなく仕組み**で作る。待ち時間だけの区画にはしない
- どんな買い順を選んでも、進行不能にはならない

---

## 1. なぜ「高難度」がむずかしいか

いまの終盤の数字を先に置く。第4区画（幻の総本店）を建て切った時点。

| もの | 値 | 出どころ |
|---|---:|---|
| 一杯の値段 | 46,018円 | `coinValue` = 55 × 1.4^20（看板メニューは上限20）|
| 開いている席 | 16 | カウンター4・テーブル3・座敷4・特上座敷3・持ち帰り棚2 |
| 席のvalueの合計 | 51.05 | `seat.value` の総和 |
| 稼ぎ | **約36万円/秒 ＝ 12.7億円/時** | 下の式 |
| 放置8時間ぶん | **約102億円** | `OFFLINE_CAP_HOURS` いっぱい |
| 強化の残り | なし | 4つとも上限。最後の1段でも約500万円 |

稼ぎの式は、エンジンが留守中の稼ぎを見積もるのと同じ考えかた（`lib/shop.ts:4098`）。

```
稼ぎ/秒 ＝ Σ(席の value ÷ 回転5.0秒) × 一杯の値段 × 0.75
```

ここから2つのことが出てくる。

**その1。いまのままだと、100億円のもの1つで8時間かかる。**
20個並べれば、それだけで160時間になる。値段を上げただけの区画は「難しい」ではなく「長い」。

**その2。既存の強化は、この価格帯では何の意味も持たない。**
両手鍋も看板メニューも、上限の1段が数百万円しかない（`upgradePrice`＝`lib/shop.ts:385`）。
第4区画に着くころには4つとも上限で、**100億円の桁に、少しずつ強くなるものが1つも無い**。

だからこの区画は、**中で稼ぎを170倍にする**ように組む。
上げ幅の中身は §6（秘伝のたれ）と §5（席の単価）に入れた。

## 2. 場所と見た目

区画は東へ1つ伸ばす。並びは第4区画までのマップの続き。

```

area-1 テーブル席  x    0..360  y 480..790

area-4 幻の総本店  x  720..1080 y   0..790
area-5 スタジアム  x 1080..1440 y   0..790   ← 足す
```

```ts
{

  label: "ラーメンスタジアムに出店する",
  price: 10_000_000_000,                       // 100億
  rect: { x0: 1080, y0: 0, x1: 1440, y1: 790 },
  padPos: { x: 1018, y: 250 },                 // 総本店の東はし
  palette: { floor: "#2f3340", deep: "#1e212b", prop: "arena" },
```

`prop: "arena"` は新しい見た目（照明塔・段になった観客席・大看板）。描画に足す（§9）。

**区画の値段（100億）は、放置の上限8時間ぶんの稼ぎ（102億）にそろえてある。**
「一晩ねかせると、ちょうど入口がひとつ買える」。ここが最後の区画への敷居になる。

## 3. 高難度の中身 ― 4つの壁

値段以外で、実際に手が止まるところを4つ作る。どれも今のエンジンの数字から出したもので、
「なんとなく大変」ではなく、**なぜ回らないかが数えられる**ようにしてある。

### 壁1. 大口注文（8杯・10杯・12杯）

この区画の席は、一度に 8杯・10杯・12杯 をまとめて出す（`SeatSpec.cost`）。
一度に運べる数はこうなっている（`lib/shop.ts:1478`, `lib/shop.ts:2695`）。

| 運ぶ人 | 一度に運べる数 | 両手鍋が上限（9）のとき |
|---|---|---:|
| プレイヤー | 3 + 両手鍋 | 12 |
| 配膳ロボ | max(5, 3 + 両手鍋) | 12 |
| ホール店員 | 3 + 両手鍋÷2 | **7** |

つまり **8杯の席から先は、ホール店員では1人も運べない**。
5人雇ったホール店員が、この区画では役に立たない。運べるのは配膳ロボと自分だけになる。
12杯の貴賓席にいたっては、**両手鍋を上限まで上げていないと誰も運べない**。

これがこの区画の第一の顔で、「人を増やせばなんとかなる」が通用しなくなる。

### 壁2. 工程 ― 特製丼は一手ではできない

ラーメン一直線で初めて、**作ったものを別の作業場へ入れる**（`takes` / `fuel`）。

```
製麺ライン ──(生麺)──┐
                      ├─▶ 仕上げ台 ──(特製丼)──▶ 特等席・貴賓席
スープ窯 ──(スープ)──┘

特大寸胴 ──(丼)────────────────────────────▶ 大観衆席
```

- 特製丼は 生麺1つ＋スープ1つ を食って1つできる（`updateStoves` の消費と同じ形）
- 仕上げ台の受け口は 生麺8・スープ8。**片方が0になった時点で止まる**
- 生麺とスープを運ぶのは、新しい職種「仕込み係」だけ。雇うまでは自分で往復する

第1〜4区画は「厨房 → 席」の一本道だった。ここで初めて**運ぶ線が3本**になる。

### 壁3. 遠さ ― 客が来るまでに10秒かかる

お客さんは歩道（x306 / y876）から歩いてくる。スタジアムの席は x1140〜1370・y494 にある。
歩く速さは96なので、**片道に10〜12秒**かかる。食べる時間は2.8秒しかないので、
このままだと席の回転は5秒ではなく14秒まで落ちる ― 席の稼ぎが 1/3 になる。

これを直すのが「スタジアム直行ゲート」。買うと、この区画の席へ行く客は
スタジアムの入口から出入りするようになる（`guestEntry`＝`lib/shop.ts:1801` を区画対応にする）。

**買うまで気づきにくく、買うと目に見えて変わる**。値段のわりに地味だが、いちばん効く1つ。

### 壁4. 直結（ベルト・配管）は、1本では足りない

作業場どうしを直結する設備（`link`）は、**0.5秒に1つしか流れない**（`lib/shop.ts:1949`）。
つまり1本あたり 2個/秒。

いっぽう席が食う量は、直行ゲートを入れた回転（5.6秒）でこうなる。

| 席 | 一度に | 回転 | 要る量 |
|---|---:|---:|---:|
| 特等席 | 10杯 | 5.6秒 | 1.79 特製丼/秒 |
| 貴賓席 | 12杯 | 5.6秒 | 2.14 特製丼/秒 |
| 合わせて | | | **3.93/秒** |

製麺ベルトとスープ配管を両方買っても、仕上げ台に入るのは 2個/秒 まで。
**足りないぶんは人が運ぶしかない。** 直結を買っても仕込み係は要る、という形にしてある。

作る速さのほうは詰まらない（仕上げ職人つきで 5.4個/秒 出る）。
この区画で詰まるのは、いつでも**運ぶところ**。

## 5. 秘伝のたれ（新しい強化）

```ts
{
  id: "tare",
  name: "秘伝のたれ",
  detail: (n) => `一杯 ${Math.round(55 * Math.pow(1.4, 20) * Math.pow(2.6, n))}円`,
  pos: { x: 1180, y: 120 },      // スタジアムの厨房のはし（通り道から外す）
  basePrice: 10_000_000_000,     // 100億
  growth: 2.15,                  // 100億 → 215億 → 462億 → 994億
  max: 4,
  unlockAfter: "seat-4-3",       // 区画を買う前から出す
}
```

- 4段の値段が、ちょうど 100億 から 1000億 までを埋める
- 効き目は `coinValue` に掛ける（`lib/shop.ts:345`）。1段で ×2.6、4段で ×45.7
- **区画を買う前から出す。** 総本店を建て切ると、たれの枠と区画の枠が同時に見える。
  「いまの店を濃くするか、東へ出るか」を最初の100億で選ばせる
  （「火のはじまり」で第2区画の枠を、便利な設備より先に見せたのと同じ考えかた）

強化の枠は買っても消えないので、**人の通り道には置かない**。
スタジアムの厨房のはし、往復の線から外れたところに置く。

## 6. 買う順番と、そのときの稼ぎ

「そのときの稼ぎ」は、それを買う直前の稼ぎ。「貯まるまで」は素直に貯めた場合の時間。

|---:|---|---:|---:|---:|

| 2 | 区画「ラーメンスタジアム」 | 100億 | 33億/時 | 3.0h |
| 3 | 特大寸胴 | 110億 | 33億/時 | 3.3h |
| 4 | 大観衆席（8杯） | 130億 | 33億/時 | 3.9h |

| 6 | 配膳ロボ 5号 | 170億 | 40億/時 | 4.3h |

| 12 | 仕上げ台 | 300億 | 104億/時 | 2.9h |

| 18 | 特製配膳ロボ | 620億 | 445億/時 | 1.4h |
| 19 | 貴賓席（12杯） | 900億 | 445億/時 | 2.0h |
| 20 | 秘伝のたれ ④ | 994億 | 835億/時 | 1.2h |

**合計 6791億円。通しで約69時間。稼ぎは 12.7億/時 → 2172億/時（171倍）。**

形として狙ったのは「**はじめが重く、後ろが軽い**」。
最初の1つは一晩ぶん（7.9時間）だが、たれ①が入った瞬間に3時間台へ落ち、
最後の1000億は1〜2時間で届く。値段は上がり続けるのに、待ち時間は短くなっていく。

15番の特等席を、18番の特製配膳ロボより先に置いてあるのはわざと。
**特製丼を運ぶ人がいない状態で、まず自分で10杯運んでみる**時間を作る。
「火のはじまり」で、はこび手を雇う前に自分で往復させたのと同じ。

### 長すぎるときのダイヤル

69時間は、この区画だけで1〜2週間ぶん（放置をはさんで）になる。
短くしたいときは、この2つを回す。値段はいじらない（100億〜1000億の帯を保つため）。

| 変えるもの | 通しの時間 | 買い切り後の稼ぎ |
|---|---:|---:|
| 案のまま（たれ ×2.6・席は 12/45/100） | 69時間 | 2172億/時 |
| たれを ×3.2 にする | 52時間 | 4983億/時 |
| 席の value を1.5倍（18/68/150） | 64時間 | 2739億/時 |
| 両方 | 50時間 | 6286億/時 |

いちばん効くのは**たれの倍率**。席の value は、いじっても総時間はあまり動かない
（席が開くのが後半なので、前半の重さに効かない）。

## 7. エンジンに足すもの

データだけでは書けない。次の8つを足す。上4つが必須、下4つは詰まりを防ぐためのもの。

### 7-1. 工程の運び手を、ステージごとに選べるようにする（必須）

いまは `isChainStage()`（＝ `takes` を持つ作業場が1つでもあるか）が true になると、
**ホール店員も配膳ロボも全員**が「作業場から作業場へ運ぶ人」に変わる（`lib/shop.ts:3472`）。

このままラーメンに仕上げ台を1つ足すと、**第0〜4区画の店員まで全員が持ち場を離れる**。
第4区画までのセーブが壊れるので、ここを分ける。

- `StageDef.haulers?: boolean` を足す。「火のはじまり」だけ `true`
- ラーメンは `false`。丼を席へ運ぶ今の動きのまま
- 新しい職種 `runner`（仕込み係）を足し、**この職種だけ** `updateHauler` を使う

### 7-2. 運ぶ品を、雇う枠ごとに指定できるようにする（必須）

いまは運ぶ品が種類で決め打ちになっている（`handledItem`＝`lib/shop.ts:2691`）。
配膳ロボは「丼」しか運べないので、**特製丼を運ぶ人が誰もいない**。

- `HireSpec.carries?: ItemKind` を足し、`Staff` に持たせる
- `handledItem` は、指定があればそれを返す
- 特製配膳ロボは `kind: "robot"` のまま `carries: "special"`

### 7-3. 区画の入口（必須）

- `EquipSpec.entrance?: Vec` を足す
- `guestEntry`（`lib/shop.ts:1801`）で、席の区画に「買ってある入口」があればそこから出す
- 帰り（`leaving`）も同じ入口へ返す。いまは `streetPos` へ一直線に戻っている

### 7-4. 秘伝のたれ（必須）

- `UpgradeId` に `"tare"` を足す
- `coinValue` に `Math.pow(2.6, levels.tare)` を掛ける
- セーブは触らなくてよい。`fromPersisted` は `upgrades` を回して 0 で埋める（`lib/shop.ts:1168`）ので、
  古いセーブは自動で `tare: 0` になる。`SAVE_VERSION` も上げない

### 7-5. 運べない席には、客を案内しない（詰まり防止）

待っている客には**あきらめる仕組みが無い**（`updateCustomers` の `waiting` は時間で消えない）。
12杯の貴賓席を、両手鍋が上限でないまま買うと、
**座った客が永久に待ち続け、その席が死ぬ**。

- `spawnCustomers` / `freeSeats` / `advanceLine` で、
  `seatCost(seat) > いま運べる最大数` の席は「空いていない」とみなす
- 長押しの説明に「いまは運べない（両手鍋 あと2段）」を出す
- 枠を買う前の説明にも同じ一文を出す

### 7-6. 留守の稼ぎを、工程に合わせる（詰まり防止）

`applyOffline`（`lib/shop.ts:4116`）は、開いている作業場をぜんぶ「丼を作るもの」として数える。
このままだと製麺ラインとスープ窯も丼を作る扱いになり、**留守のほうが儲かる**。

- 席が受け取る品（`main` / `special`）を作れる作業場だけを数える
- 工程の作業場は、上流がそろっているぶんだけを数える（細いところで決める）

### 7-7. 配膳ロボも、担当の区画を先に見る（あると良い）

ホール店員は自分の区画を優先するが、ロボは「待っている順」で選ぶ（`lib/shop.ts:3519`）。
このままだと、屋台のロボが1000px 歩いてスタジアムまで出張してくる。
ロボにも区画の重みを入れる。

### 7-8. 見た目（あると良い）

- `AreaPalette.prop` に `"arena"` を足す。段になった観客席・照明塔・大看板
- 仕上げ台の見た目（`art: "finish"`）。生麺とスープの受け口を2つ並べて描き、
  **どちらが切れているかが立ったまま分かる**ようにする
- 8杯・10杯・12杯 は、頭の上に積み上がる丼の絵が長くなりすぎるので、
  6杯から上は「6杯＋×2」のように数字でまとめる

### やらないと決めたこと

- **自動配膳機（`autoServer`）は使わない。** 使うと `buildPads`（`lib/shop.ts:451`）が
  **全ステージの全席に**枠を作る。屋台のカウンター席に2,500円の自動配膳機が並んで、
  序盤が丸ごと壊れる。この区画の自動化は、直結（ベルト・配管）と特製配膳ロボで足りる
- **行列（`queue`）は入れない。** ステージ全体の設定なので、第0区画の遊びが変わってしまう
- 集客のオブジェクトは足さない（§4の最後）

## 8. 進行不能を作らないための決めごと

買う順番は自由なので、どの順でも止まらないことを先に決めておく。

1. **運べない席には客を入れない**（§7-5）。買ってしまっても、両手鍋を上げれば動きだす
2. **仕上げ台は、片方だけでも受け取る。** 生麺だけ入れてもスープだけ入れても詰まらない。
   仕込み係は「少ないほうから入れる」順で運ぶ（生麺8・スープ0 のような偏りを作らない）
3. **特製丼が作れないあいだも、大観衆席は普通の丼で回る。** 工程が止まっても稼ぎは0にならない
4. **直行ゲートを買わなくても遊べる。** 回転が遅いだけで、詰まりはしない
5. **区画を買った直後に何も買えない、が起きないようにする。** 区画が開いた時点で
   特大寸胴（110億）・大観衆席（130億）・直行ゲート（150億）の3つが同時に見えている

## 9. 確かめかた

「火のはじまり」と同じく、案内どおりに動く自動プレイヤーで測る。見るのはこの5つ。

| 見るもの | 目安 |
|---|---|
| 区画をひらくまで | 放置1回（8時間）ぶんで届くか |
| 買い物と買い物のあいだ | 前半4〜6時間、後半1〜2時間。**後ろへ行くほど短いこと** |
| 仕上げ台の止まっている時間 | 全体の20%以下（超えるなら受け口8を増やすか、仕込み係を安くする）|
| 貴賓席が空席のまま待つ時間 | 30秒以上待たせない（運搬が足りていない合図）|
| 荷物を持ったまま5秒以上止まる | 0回。起きたら運び手の優先順を見直す |

`docs/fire-early-game.md` と同じで、**素振りは人間より遅い**。
まとめて積んで回る人が遊べば、この表より速く進むはず。

## 10. まだ決めていないこと

- **クリアの扱い。** 貴賓席を買ったら何が起きるか。いまは何も起きない（買い切って終わり）。
  「ドリームパーク」への橋渡しを出すか、称号を出すかは決めていない
- **特製丼の見た目。** 丼と見分けがつく必要がある（金の縁か、湯気の色を変えるか）
- **スタジアムの音。** 歓声の層を足すかどうか。`lib/bgm.ts` は区画ごとに層を変えられる
- **仕込み係の2人目以降。** いまは1人だけ。素振りで足りなければ、
  700億あたりに2人目を足す（そのぶん通しの時間は伸びる）
